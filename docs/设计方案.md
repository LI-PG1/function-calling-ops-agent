> **文档性质**：系统设计方案（施工用）｜版本 **v0.2**｜2026-07-29

> **设计总则**：**锁定项目类型，细节自由调整**——类型＝「多工具 Function Calling ＋ 长链路任务 ＋ 生产级可靠性工程 ＋ 评测」；场景细节、工具集、规则库内容均可调整。
> **项目方向**：Function Calling 工具调用链 / 容错与并发控制的工程实现。

## 1. 项目定位

**项目背景**（可直接用于 README / demo 文案）：

> 出行服务是一条长链路：用户一句"我有点困"，背后可能是疲劳风险而非播放音乐；临时改目的地、找不到上车点、孩子在后排——需求藏在没说出口的话里，处置要组合车控、导航、订单、客服多个系统，还要守住安全边界。本项目围绕这一场景自建合成规则库与 mock 工具服务，实现出行服务编排 Agent：三层路由识别身份与场景风险，多步任务自动规划并调用工具形成服务闭环，双层护栏兜底安全，失败重试、超时控制、并发与降级下的稳定性全程可验证。

**实现范围**：模拟场景与 mock 服务均自行设计实现；工程链路（路由 / 编排 / 护栏 / 可靠性 / 评测）完整落地，评测数据全部来自本工程实测。

**类型锁定（不变）**：多工具 Function Calling；入口分流（场景标签路由）；多步任务规划执行；**安全边界（双层护栏）**；可靠性工程（重试/超时/并发/降级）；评测含失败注入与安全专项。

**技术纵深**：Function Calling / 编排 / 后端工程 / 技能迭代 / 评测——各环节展开到实现细节与实测数据（深化设计见 §2 对应小节）。

**细节可调（当前建议）**：场景＝出行服务双模式（车主自驾 + Robotaxi）；工具＝13 个（可调）；规则库＝合成（可调）；视觉工具＝二期可选。

## 2. 系统设计

**链路总览（v0.2）**：

```
用户请求（自然语言 ＋ 车辆/订单状态上下文）
 → ① 三层路由：规则快路径（高危关键词/行驶态硬规则，毫秒级拦截）
              → LLM 场景标签（8 类场景 × 身份：车主/Robotaxi 乘客 × 风险等级）
              → 宽表兜底（chat 轻量应答）
 → ② Agent 循环：Plan（整体计划）→ 选择工具（按模式动态装载）→ 并行/串行调用
              （JSON Schema 校验入参 ＋ pre_check 危险拦截）→ 合并 observations
              → 判继续/结束 → Critic 自检（含安全审查）
 → ③ 输出协议四件套：自然语言回复 ＋ 结构化服务计划（每步 reason）＋ 禁止动作列表 ＋ 安全提示
 → ④ 转人工兜底（critical 风险/连续失败降级/用户要求 → escalate_human）
```

**三段式调用范式**（行业共性打法）：先建上下文（`get_vehicle_status`）→ 风险评估（`assess_risk`）→ 服务执行（车控/导航/订单）——每段失败均触发可靠性机制。

**工具清单（JSON Schema 注册，13 个）**：

| # | 工具 | 模式 | 说明 |
|---|---|---|---|
| 1 | `get_vehicle_status()` | 共用 | 车辆状态（位置/电量/行驶态/行程） |
| 2 | `assess_risk(situation)` | 共用 | 风险评估（规则库 + LLM）→ 风险等级与策略 |
| 3 | `search_safety_rules(query)` | 共用 | 安全规则库检索（Embedding） |
| 4 | `control_climate(action, zone?)` | 车主 | 空调（制冷/制热/风量/除雾） |
| 5 | `control_seat(action, zone)` | 车主 | 座椅（通风/加热/按摩/放倒） |
| 6 | `navigate(destination)` | 车主 | 导航设置 |
| 7 | `find_parking(near?)` | 车主 | 停车场查询 |
| 8 | `find_charging(near?)` | 车主 | 充电站查询 |
| 9 | `play_media(category)` | 车主 | 提神媒体（疲劳场景配合提醒，不单独作为处置） |
| 10 | `query_ride_order(order_id?)` | Robotaxi | 订单查询 |
| 11 | `modify_pickup_point(order_id, point)` | Robotaxi | 修改上车点 |
| 12 | `change_destination(order_id, destination)` | Robotaxi | 修改目的地 |
| 13 | `escalate_human(reason, priority)` | 共用 | 转人工客服 |

（可选第 14：`identify_scene(image)` 视觉识别——VLM，放二期）

**工具动态装载**：路由输出的身份标签决定工具子集（车主 9 个 / Robotaxi +4 个）——避免"一个万能 Prompt 包打所有工具"。

**可靠性工程（施工清单，逐项落进代码）**：

1. **异常向上传播**：工具异常必须被编排层感知（禁止 try-except 吞掉）——"失败不能被吞"是本项目第一纪律；
2. **重试**：工具失败 → 视为"非结果" → 带错误信息重试（上限 N 次）；指数退避；
3. **逐工具超时**：per-call timeout；超时按失败处理；
4. **并发控制**：Semaphore 限制并行工具数/全局并发，防雪崩；
5. **max_iter 硬限**：循环上限（如 8），触顶 → 降级输出（已完成步骤 ＋ 建议）；
6. **降级**：连续失败/超限 → 友好降级话术 ＋ 转人工指引；
7. **失败注入**：mock 服务内置注入开关（超时 / 500 / 空结果）——用于验证以上机制（评测素材）。

**安全边界（双层护栏 ＋ 声明式规则库）**：

- **L1 提示词层**：系统提示注入场景策略；每次工具调用带 reason（可解释）；
- **L2 代码硬规则层**（"模型失误仍有代码兜底"）：`pre_check` 危险动作前置拦截（行驶态开门/解安全带类指令、超速设定、儿童独留车内关闭温控、无订单状态修改上车点）；`post_review` 输出后校验（高风险场景输出必须含安全提示与禁止动作列表，否则打回重写）；
- **声明式规则库** `config/safety_rules.yaml`：`{ id, scene, risk, strategy: [allow/remind/refuse/degrade/escalate], must_output }`——规则可版本化，"规则迭代"成为 CHANGELOG 的一类条目（漏拦 → 补条；误拦 → 调条件）；
- **转人工兜底（HumanAgent）**：`escalate_human` 触发条件＝critical 风险 / 连续失败降级 / 用户显式要求；客服 mock 工单承接。

**技能体系（Skills）与迭代循环**：

- 技能＝工具的能力化封装，一技能一目录：`skills/<name>/skill.yaml`（名称 / 版本 / 描述 / JSON Schema / 调用示例 / 失败处理策略）＋实现＋评测样例；注册表统一装载，供模型选型与编排层调度；
- **评测驱动迭代循环**：跑任务集 → 失败分类（技能选择错 / 参数错 / 缺技能 / 描述歧义 / 后端错）→ 定向修改（描述 / schema / 拆合技能 / 补技能）→ 回归测评 → 写入 `skills/CHANGELOG.md`（版本 ＋ 原因 ＋ 前后指标）；
- 迭代指标：技能选择准确率 / 参数填充准确率 / 调用成功率——"迭代前后"可证。

**相关后端（服务侧）**：

- mock 服务按真实后端形态建设：REST 语义（状态码 / 统一错误体）、错误分类（TIMEOUT / NOT_FOUND / CONFLICT / INVALID）、工单创建幂等、SQLite 持久化、健康检查；
- Agent 服务端（M4）：对话入口 API ＋ 会话管理（多轮上下文）＋ 工具调用留痕（可回放排查）＋ 结构化日志。

**模型与组件**：见 `模型选型.md`——主 FC 选 Qwen3-Coder-Next（部署；对照 35B-A3B 零成本档）、轻量档 Qwen 系 4B 级、Critic 与评测 Judge 选 DeepSeek V4-Pro（API）、Embedding 选 Qwen3-Embedding-4B（与主 FC 同机部署）；向量库 ＝ Milvus Lite / Chroma。

## 5. 评测设计

- **功能指标**：多步任务完成率（对照"无规划基线"）；工具调用准确率（序列/参数比对）；路由准确率（8 类场景标签）与分流延迟。
- **技能指标**：技能选择准确率 / 参数填充准确率——用于技能迭代的前后对比。
- **安全指标（v0.2 核心）**：**危险请求拦截率**（危险子集：pre_check + post_review 双层，目标 100%）；输出合规率（高风险场景输出含四件套的比例）；**护栏误拦率**（安全与可用性的平衡，单列分桶）。
- **可靠性指标**：失败注入下完成率；重试成功率；并发压测 P50/P95；超时率；max_iter 触顶率。
- **失败模式分布**：工具误选 / 参数错 / 超时 / 规划错 / **护栏误拦（新桶）** / 规则漏拦（新桶）/ 降级触发——分桶统计（报告核心图）。
- **安全对照实验（v0.2）**：无护栏 vs 双层护栏的同危险子集拦截率对比——量化 L2 代码规则的价值；规则库 v1 vs v2 迭代前后误拦/漏拦对比。
- **外测对照**：BFCL / API-Bank / MCPToolBench++（函数调用准确率口径，沿用）。
- **产出**：`eval/report.md` ＝ 指标表 ＋ 失败分布 ＋ 安全专项表 ＋ 典型案例。

## 9. 设计问答（常见追问与对应实现）

- 工具调用失败/超时怎么处理？（异常向上传播 ＋ 非结果重试 ＋ 退避 ＋ 超时——带注入测试数字）
- 多步任务怎么"不迷路"？（Plan-then-Execute ＋ max_iter 硬限 ＋ 降级）
- 并发下怎么稳？（Semaphore ＋ 逐工具超时 ＋ 压测 P95）
- 入口分流为什么重要？（成本与延迟——简单问题不进 Agent 循环）
- Agent 怎么评测？（任务集 ＋ 失败模式分布 ＋ 失败注入）
- 工具注册怎么做规范？（JSON Schema ＋ 入参校验 ＋ 统一结构化返回）
- 技能（工具）怎么迭代优化？（评测驱动：失败分类 → 描述 / schema 优化 → 回归——带前后数字）
- 后端怎么支撑 Agent 稳定性？（错误分类 / 幂等 / 调用留痕）
- **安全边界怎么守**（v0.2）？（L1 提示词 + L2 代码硬规则双层护栏；危险请求拦截率与误拦率实测——模型会失误，代码兜底）
- **怎么理解"没说出口的需求"**（v0.2）？（场景路由 + 风险分级："我有点困"→ 疲劳风险 ≠ 播放音乐——带场景识别准确率数字）
- **工具多了怎么办**（v0.2）？（按身份/模式动态装载子集——避免万能 Prompt，带路由延迟对比）
- **转人工怎么设计**（v0.2）？（触发条件三选：critical 风险 / 连续失败降级 / 用户要求——兜底也是闭环一部分）
