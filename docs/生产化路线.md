# 生产化路线（ops-agent）

> 目的：把「研发验证工程」与「生产系统」之间的差距**显性化**——现状到生产，每一环差什么、怎么补、量级多大。
> 本文不是承诺清单，而是**迁移地图**；所列"现状"全部有仓库内证据（代码位置 / 报告 / 实测数字）。

## 一、已经是「生产模式」的部分（设计层，可直接迁移）

| 机制 | 实现位置 | 生产对应物 |
|---|---|---|
| 三层路由（规则快路径 → 轻量档 4B → 主 FC 模型） | `src/router.py` | 成本 / 延迟分层策略 |
| 动态工具装载（车主 9 / Robotaxi 13，按模式注入） | `src/tools/spec.py` + `agent/loop.py` | 按场景裁剪动作空间（防误调用） |
| 双层护栏（L1 提示词约束 ＋ L2 代码硬规则；声明式安全规则库） | `agent/loop.py` + `safety_rules`（升级设计） | 安全边界与合规前置 |
| 可靠性（调用超时 / 退避重试 / 并发闸 / 死循环防御 / 失败路由） | `src/reliability.py` | 生产可靠性工程 |
| 可解释（逐工具调用携带 reason；全链路可回放） | `agent/loop.py` | 可审计 / 可追责 |
| 评测（BFCL v3 五类 1240 条 → 90.0%；简化比对口径已声明） | `eval/run_bfcl.py` → `eval/report_bfcl.md` | 离线评测门禁（CI 前置） |

## 二、差距矩阵（现状 → 生产要求）

| 维度 | 现状 | 生产要求 | 迁移动作 | 量级 |
|---|---|---|---|---|
| 服务对接 | mock 服务（设计使然：场景可控、可复现） | 真实车云 / 导航 / 补能 / 订单 API | 适配层按接口分域实现：鉴权、幂等、SLA、降级预案 | 周 |
| 鉴权与审计 | 无（本地演示） | API 网关鉴权、调用审计留痕 | 接入网关 + 审计日志（谁在何时调了哪些工具） | 周 |
| 并发与配额 | 进程内并发闸 | 多用户会话隔离、队列与限流 | 会话存储 + 队列 + 配额 | 周 |
| 安全规则运维 | 规则文件（声明式） | 版本化 / 热更新 / 回滚 / 命中评测 | 规则库版本管理 + 灰发 + 命中率面板 | 周 |
| 可观测 | 运行记录 / trace | 指标（分流比例、护栏触发率、失败率、P95）+ 告警 | 接 Prometheus / OTel | 周 |
| 人工兜底 | 转人工设计存在（HumanAgent） | 真实坐席系统对接 | 工单 / 坐席 SDK 对接 | 周 |
| 质量门禁 | 手动跑评测 | CI 门禁（回归不过不发布） | 评测脚本接 CI（BFCL 抽样 + 场景任务集） | 天 |
| 语音 / 多模态入口 | 文本接口 | 车机语音链路（ASR/TTS） | 入口层扩展（与编排解耦） | 周 |

## 三、分阶段路径

- **P0（本阶段）**：v0.2 施工——素材层 → 路由 → 护栏 → 8 场景任务集与评测驱动迭代（进行中）。
- **P1 真实服务对接**：mock → 适配层（分域：导航 / 补能 / 订单 / 车控），含鉴权、幂等与超时降级。
- **P2 服务治理**：网关鉴权 + 审计 → 会话队列与限流 → 指标告警 → CI 评测门禁。
- **P3 组织级**：安全规则热更新与灰发、坐席对接、语音入口、合规审计。

## 四、评审要点（一页答案）

- **"数据是 mock 的？"** —— 场景数据是 mock（设计使然：能力验证在本地 Demo 可体验，可控可复现）；能力证据走公开基准（BFCL v3 1240 条 → 90.0%）与场景任务集；生产化差距集中在"服务对接层"，见 §二首行。
- **"能上生产吗？"** —— 以"直接部署"为标准：不能，缺的是一层交付治理（见 §二、§三）；以"设计可迁移性"为标准：路由分层、动态装载、双层护栏、可靠性、可解释、评测闭环均在，迁移动作逐项可执行。
